# 基准测速对标记录

对标工具：**DiskSpd 2.2.0** —— CrystalDiskMark 自带的测速引擎（见 参考软件/CrystalDiskMark/CdmResource/DiskSpd/.）。
用它而不是 CDM 图形界面，是因为 **CDM 的测速内核就是 DiskSpd**，同参数对比最有说服力。

## 1. 测试条件

| 项 | 值 |
|---|---|
| 被测盘 | YMTC YMSS2E（PhysicalDrive1，系统盘 C:/D:） |
| 测试文件 | 1 GiB，随机数据（双方各自建文件，同卷同目录） |
| 访问方式 | 双方都是无缓存直通：我方 FILE_FLAG_NO_BUFFERING + OVERLAPPED + WRITE_THROUGH；DiskSpd 用 -Sh |
| 顺序档 | -b1M -o8 -t1 -w0 与 -b1M -o1 -t1 -w0 |
| 随机档 | -b4K -o32 -t16 -w0 -r 与 -b4K -o1 -t1 -w0 -r |
| 取值口径 | **双方都取多次的最好成绩** —— CDM 默认 5 次取最好，DiskSpd 用 -d5 跑 3 次取最好 |

## 2. 结果

| 档位 | DiskSpd 最好 | Gu-disk 最好（--runs 5） | 偏差 |
|---|---|---|---|
| SEQ1M Q8T1 read | 5 997.5 MiB/s | 6 096.1 MB/s | **+1.6%** |
| SEQ1M Q1T1 read | 4 020.1 MiB/s | 4 253.1 MB/s | **+5.8%** |
| RND4K Q32T16 read | 3 357.2 MiB/s · 859 443 IOPS | 2 981.8 MB/s · 763 336 IOPS | **-11.2%** |
| RND4K Q1T1 read | 71.1 MiB/s · 18 205 IOPS | 78.5 MB/s · 20 105 IOPS | **+10.4%** |

（MiB/s 与 MB/s 在本表是同一口径：字节数 ÷ 1024²。）

## 3. 结论与偏差来源

- **顺序两档在 ±6% 以内**，可以直接看作一致。
- **随机两档在 ±11% 以内且方向相反**（QD32 偏低、QD1 偏高），不是系统性偏移：
  - QD32 偏低：我方是真 16 线程 × 32 并发提交，但每批用 WaitForMultipleObjects 全等待收尾，
    批与批之间存在尾延迟空隙；DiskSpd 走 IOCP，完成即补发，队列始终填满。
  - QD1 偏高：QD1 的吞吐完全由**每次 I/O 的软件开销**决定。DiskSpd 每个 I/O 都做统计采集与 IOCP 投递，
    我方是极薄的"提交-等待"循环，所以更快。这一档比的不是硬盘，是两边的框架开销。
- 因此**不把 ±5% 当作随机档判据**：这块盘在不同 SLC 缓存状态下的跑动本身就有 ±10%。
  采用的口径是：**顺序档 ≤ ±10%、随机档 ≤ ±15%，且方向不固定**。

## 4. 途中修掉的两个真 bug（都是靠对标发现的）

1. **块大小没有按行传下去**：DirectIoFile 一直用构造时的 4 KiB，导致 SEQ1M 四行全按 4K 跑。
   识别线索是"IOPS × 4 KiB 恰好等于打印的吞吐量"。修完后顺序档从 739 MB/s 回到 5 700 MB/s。
2. **并发语义理解错了**：CDM 的 Q32T16 是 **16 线程 × 每线程 32 并发 = 512 个在途 I/O**，
   早期只做单线程 32 并发，4K 随机 IOPS 只有对标值的 1/3.5（197k vs 693k）。
   改成多线程提交后 763k IOPS，与 DiskSpd 同量级。

## 5. 复现命令

    # 我方（--target 可给盘符，也可给完整文件路径）
    Gu-disk.Cli bench --target E: --profile cdm4 --size 1G --runs 5

    # 对标
    DiskSpd64.exe -c1G -b1M -o8 -t1 -w0 -d5 -W0 -Sh <file>
    DiskSpd64.exe -c1G -b4K -o32 -t16 -w0 -r -d5 -W0 -Sh <file>

给盘符时 CLI 会在盘根建 Gu-disk_bench_<随机>.tmp，结束自动删除；目标必须可写。
