# Gu-disk 外观规范（v2 定稿）

> 设计定位：**仪器台 / Instrument**，不是 SaaS 卡片风。
> 定稿渲染：`reference/mockup/v2/`（overview.html、smart.html、overview-light.html + 三张 1280×840 PNG）。
> **实现必须遵守本文**；尤其是文末「与参照软件的差异」一节，偏离即视为跑回参照的样子。

---

## 1. 设计原则

1. **设备优先**：磁盘本身是主视觉与导航（顶栏设备芯片），不是藏在侧栏里的一个页面。
2. **结论先行**：进页面第一眼是"这块盘能不能用"（大号分数 + 一句话结论），明细在其后。
3. **数字是主角**：等宽字体、大号、右对齐、千分位用空格（`23 507 343 456`）。
4. **零装饰**：没有 emoji、没有卡片投影、没有渐变按钮；层次靠 1px 发丝线与表面明度差。
5. **长任务不丢**：任何耗时操作都落到常驻任务台，可离开当前页。
6. **颜色只表状态**：颜色不是装饰。青柠=品牌与"当前选中"，绿/琥珀/红=状态，蓝=读取，青柠=写入。

## 5. 组件规范

### 5.1 设备芯片 `.chip`
高 40px，2 行：主行型号（12.5px/600，超长省略）、副行 `盘符 · 协议 · 容量 · 温度`（10px 等宽，色 `--t3`）。
左缘 5px 处一条 3px 圆角色条 = 状态：健康 `--ok` / 注意 `--warn` / 危险 `--bad` / 未透传 `--warn`。
选中态：描边 `--lime-line` + 面 `--surface3` + 底边 2px 青柠内阴影。

### 5.2 结论横幅 `.hero`
三列网格 `200px | 1fr | 268px`，外加跨三列的结论行。

- 第 1 列：微标签「总体状态」→ **大号档位词**（正常青柠 / 注意琥珀 / 警告琥珀 / 危急红）→ 计数行（严重 N · 警告 N · 注意 N）→ 磁盘型号
  - **不再有打分**：早期用加权公式折算 0-100 分，那个数字是公式产物而非盘的客观事实，已废弃。现在只出四档档位词，判据全部来自 SMART 谓词。
- 第 2 列：微标签「结论」→ 一句话总结；下方「介质类型判定」给出介质档位、置信度与依据。**判定依据与已核对项放在右下卡片**：异常项 = 级别标签 + 来源属性 + 原始值 + 判读 + 建议；正常项 = 紧凑双列列出，让人看见核对了什么。下方 11.5px 说明文字，写明**未评估项**（例：型号 TBW 未知）
- 第 3 列：4 条快速指标（综合温度 / 已用寿命 / 通电时长 / 启停次数），左标签右数值，数值 19px 等宽，温度按状态着色
- 结论行：顶部 1px 分隔线；`结论` tag + 一句话（主句加粗）+ 右侧来源 tag（协议 / 链路）

### 5.3 模块 `.mod`
面 `--surface`、1px `--line` 描边、圆角 8px、内边距 13/15px。
标题行：微标签 + 右侧补充信息（11px，色 `--t3`）。
模块内的定义列表：`dt` 色 `--t3`、`dd` 等宽右对齐，行距 7px。

### 5.4 风险行 `.risk`
`ID(26px 等宽, --t3)` + 名称（1fr，色 `--t2`）+ 数值（等宽 600，右对齐 min 56px）+ 状态 tag。
行间 **虚线** `1px dashed --line`，最后一行无。

### 5.5 属性表
- 固定列宽（table-layout: fixed）。列：状态色条 10px / ID 34px / 属性名+英文（1fr）/ 当前 48 / 最差 48 / 阈值 48 / 原始值 228 / RAW Hex 118 / 状态 60
- 行高 26px（padding 5px 10px），字号 12.5px，**偶数行不提亮**，仅选中行染 `--lime-dim` + 左缘 2px 青柠
- 每行最左一条 2px 竖条表严重度：正常 `--ok` / 注意 `--warn` / 危险 `--bad` / 统计 `--blue`（统计类弱化到 55% 透明度）
- 属性名单元格：中文名（12.5px/600）后跟英文标识（10.5px 等宽 `--t3`），同一行，间距 8px
- NVMe 无"当前/最差归一化值"，一律显示 `—`；阈值列显示规格值（例 `10 %`）

### 5.6 解读抽屉 `.drawer`
宽 344px，固定右侧。结构：ID 徽标 + 中文名 + 英文标识 + 状态 tag → 分隔线 → 主数值（30px 等宽）+ 单位 + 右上 RAW 分解 → 若干"微标签 + 正文"段落（含义 / 正常范围 / 当前解读 / 历史 / 建议）→ 底部两个动作按钮（主按钮青柠底）。
正文 12.5px，行高 1.62。

### 5.7 任务台 `.dock`
高 58px，顶部 1px 线。左侧「任务台」微标签，随后是任务芯片（可多个）：
`任务名(12.5/600)` + 5px 进度槽（进行中青柠 / 暂停琥珀）+ 百分比（等宽 600）+ `速度 · 剩余` + 暂停/继续/取消两个 22px 小按钮。
右端显示队列数与提示语。空态：`无运行中的任务 · 测速 / 扫描 / 自检会在这里排队`。

### 5.8 其他
- 输入框：高 32px，面 `--surface2`，圆角 5px，聚焦描边 `--lime-line`
- 分段控件 `.seg`：外框 1px，段间 1px 竖线，选中段青柠底 + 青柠字，段内数字用等宽
- 图标按钮：30×30，1px 描边，线性图标 stroke 1.6–1.8px

## 附录 A · 控件模板规范（v2 美化后定稿）

**铁律：WPF 的默认控件模板全部使用系统色，深色主题下必然出现白底/白表头/白选中/浅滚动条。
凡是用到的控件，一律自绘 ControlTemplate，不依赖默认外观。**

| 控件 | 默认外观的问题 | 本项目的做法 |
|---|---|---|
| Button | 系统渐变描边 + 方角 | 圆角 6、高 32、内边距 16/0；主操作青柠实心（悬停提亮、按下压深）、次级发丝描边（悬停浮起底色）、图标按钮 30×30 圆角 7 |
| ComboBox | **白底**（模板写死系统色，控件设 Background 无效） | 自绘 ToggleButton + Popup；下拉面板带 8px 圆角与投影 |
| ComboBoxItem | 白底高亮 | 透明常态、悬停 Surface3、选中 LimeDim |
| ListView | 白色外框 | 背景透明、无边框 |
| ListViewItem | **白底选中** | 圆角 6；悬停 Surface2；选中 LimeDim + **左侧 2px 青柠竖条**；模板用 GridViewRowPresenter 承接列 |
| GridViewColumnHeader | **白底表头** | 透明底 + 底部发丝线；11px 加粗弱色、左对齐、高 30 |
| ProgressBar | 系统三段式 | 细轨道（高 6~8）+ 圆角填充，用 TemplateBinding 承接局部 Foreground/Background 覆盖 |
| CheckBox | 系统方框 | 自绘 16×16 圆角 4；悬停青柠描边；勾选青柠填充 + 深色对勾 |
| ScrollBar | 浅色带箭头 | 宽 8、无箭头（翻页区透明 RepeatButton）、圆角滑块 Line2、悬停不变亮、拖拽时 Text3 |
| TextBox | 白色内陷 | Surface2 底 + 发丝描边 + 6 圆角；聚焦青柠描边；光标青柠 |
| ToolTip | 系统浅黄 | 深色 Surface3 + 发丝描边 + 6 圆角 |

**按钮态色令牌**：`Brush.Lime` 常态、`Brush.LimeBright` 悬停、`Brush.LimeDeep` 按下，
深/浅两套令牌文件都要有，靠 `DynamicResource` 自动跟随主题切换。

**页签**：不用边框，用**底部 2px 青柠下划线**指示选中（`TabRadio`），选中态文字转青柠并加粗。

### A.2 属性表两列口径

S.M.A.R.T. 属性表的**「原始值（十进制）」与「原始值（十六进制）」必须指向同一个字段整数值**，
换算结果（℃ / % / TB）只写进文本描述里。列头要显式标出进制，否则用户会以为两列是两个不同的值。

踩过的坑：温度行的十六进制曾用"磁盘原始字节序"（39 ℃ 显示 `3901`，即 0x0139 低字节在前），
而其它行用的是"数值的十六进制"（`ToString("X16")`）—— **同一列两种口径**，
看上去就是"两列对不上"。现在统一为数值形式：39.9 ℃ 显示 `0139`（313 K），十进制列同时写"39.9 ℃（313 K）"。

**一句话判据**：截图里出现任何一块比 `Brush.Surface` 更亮的**长方形色块**，就是漏了自绘模板。

### A.1 主题切换的硬规矩

**只替换"令牌字典"，且必须按 `Source` 查找，不要按索引替换。**

踩过的坑：早期把 Tokens + Metrics + Styles 合成一本 `Theme.xaml`，`App.xaml` 只合并它。
切主题时写的是 `MergedDictionaries[0] = new ResourceDictionary { Source = Tokens.Light.xaml }` ——
`[0]` 其实是**整本 Theme.xaml**，于是样式与度量全被丢掉，只剩颜色令牌。
症状：主题"切成功了"（底色变了），但**所有自绘模板消失** —— 页签退回系统单选圆圈、
按钮退回 3D 边框、卡片失去圆角。截图里一眼可见。

现在：

```xml
<!-- App.xaml：[0] 令牌 / [1] 度量 / [2] 样式，三本并列 -->
<ResourceDictionary Source="Themes/Tokens.Dark.xaml"/>
<ResourceDictionary Source="Themes/Metrics.xaml"/>
<ResourceDictionary Source="Themes/Styles.xaml"/>
```

```csharp
// 按 Source 定位，索引重排也不会失效
for (int i = 0; i < dicts.Count; i++)
    if ((dicts[i].Source?.OriginalString ?? "").Contains("Tokens.")) { dicts[i] = next; break; }
```

**判据**：切主题后若出现任何系统默认控件外观（单选圆圈、3D 按钮、白表头），就是替换错了字典。

**另**：`Themes/Theme.xaml` 已删除 —— 留着这种"总入口"文件正是上述 bug 的成因。
