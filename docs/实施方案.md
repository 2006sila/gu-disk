# Gu-disk 实施方案

技术栈 **C# / .NET 9 + WPF**，单文件绿色版，**零 NuGet 第三方包**；不装内核驱动，纯用户态 DeviceIoControl。
外观必须遵守 `docs/外观规范.md`。

## 0. M1 实测记录（都是真机跑出来的，不是推断）

| 结论 | 细节 |
|---|---|
| NVMe 身份必须用 Identify Controller | Windows 在 STORAGE_DEVICE_DESCRIPTOR 里给 NVMe 的序列号是"ASCII 的十六进制分组"形式（实测 `3530_3330_3138_3330_50C6_8E09_5053_4248.`），**不能当序列号用**。改从 Identify(CNS=1) 取：SN@0x04/20、**MN@0x18**/40、FR@0x40/8。（MN 写成 0x14 会多吃 4 字节序列号尾巴，踩过） |
| NVMe 身份 + 健康日志**免管理员可读** | `IOCTL_STORAGE_QUERY_PROPERTY` + `StorageDeviceProtocolSpecificProperty`（协议数据放**偏移 8**，不是 12；Identify CNS=1 / LogPage 0x02）。实测非提升进程读到 512 B 健康日志，温度与 CDI 一致。ATA 直通与裸盘读写仍需管理员（Win32 5）。 |
| 协议查询写错会得到 Win32 87 | ERROR_INVALID_PARAMETER。输入缓冲布局：`[0..4) PropertyId [4..8) QueryType [8..) STORAGE_PROTOCOL_SPECIFIC_DATA`，输入长度按 winioctl.h 取 `sizeof(QUERY)+sizeof(PSD)-1`。 |
| SetupAPI 两个坑 | `SetupDiGetDeviceInstanceIdW` 的第二参是 **SP_DEVINFO_DATA**（不是 SP_DEVICE_INTERFACE_DATA）；`char[]` 参数必须显式 `[Out]` 否则只入不出。更省事的做法：`SetupDiGetDeviceInterfaceDetailW` 直接 out 一个 SP_DEVINFO_DATA，拿 **DEVINST** 向上追溯控制器 / USB 桥接，不必再用实例 ID 反查。 |
| 读写量是 **1024 进制** | CDI 的 HostReads="12028"/HostWrites="5510"（GB 口径）与我们按 1024³ 算出的 12028 / 5511 逐字吻合；用 1000 进制会得到 12915，对不上。已写进回归测试 `nvme.matches-cdi`。 |
| smartctl 的 Windows 设备名是 `/dev/sdX` | 传 `\\.\PhysicalDriveN` 会报 `Invalid argument`（exit 2）。`--scan` 的枚举顺序**不保证**与 PhysicalDriveN 同序，所以层 2 引擎靠 **序列号匹配** 定位设备（`--scan` → 逐个 `-i -j` 取 serial → 建映射）。 |
| smartctl 读 NVMe **也不需要管理员** | 与本机原生路径一致；实测 exit 0，15 个字段与原生逐项吻合。 |
| 交叉校验必须区分"状态量"与"累计计数器" | 系统盘在两次读取的 130 ms 间隔内，写命令计数就涨了 13 —— 计数器只校验"没有倒退且增量在容忍范围内"（max(1000, 0.1%)），状态量（严重警告 / 备用空间 / 寿命 / 介质错误 / 错误日志）才要求严格相等。UI 上把计数器的增量作为注解显示，不报错。 |

## 0.1 WPF 运行环境坑（实机踩到）

| 现象 | 根因 | 处置 |
|---|---|---|
| 界面线程 NRE，崩在 `RefreshPanes()` | XAML 里 `IsChecked="True"` 会在 `InitializeComponent()` **期间**触发 `Checked`，那时具名控件字段还没赋值 | `RefreshPanes()` 开头判断所有具名控件非 null 再继续 |
| `UnauthorizedAccessException: Access to the path '%TEMP%\WPF' is denied` | WPF 需要在 `%TEMP%\WPF` 建临时目录；受限环境下子进程写不了 C 盘用户目录 | 启动前把 `TEMP`/`TMP` 指到可写目录；正常用户环境不受影响 |
| 截不到界面（抓到别的窗口） | 驱动做前台动作后会还原前台，截屏抓到的是压在它上面的窗口 | 用 `PrintWindow(hwnd, hdc, PW_RENDERFULLCONTENT=2)` 让窗口自己渲染，不受遮挡影响 |

## 1. 成功判据

1. 在三块 NVMe（Predator GM7 2TB / KIOXIA EXCERIA PLUS G3 / YMTC YMSS2E）上，**每个字段与 CrystalDiskInfo 9.6.0 一致**，属性中文名逐字一致。
2. ~~健康分数采用参照公式作基线~~ —— **已废弃**：加权折算出的分数是公式产物而非盘的客观事实，改为四档状态判定 + 逐条可追溯的依据。
3. 至少 1 个 USB-SATA 盒、1 个 USB-NVMe 盒能读出 SMART；读不到时必须给出**逐协议探测证据表**与"盒子不透传"结论。
4. 与 CrystalDiskMark 8.0.1 同盘同参对比：SEQ1M Q8T1、RND4K Q32T16 偏差 ≤ ±5%。
5. `tools/verify.ps1` 全绿；发布包内零驱动、零网络、零 NuGet 包。

## 4. 模块要点

### 4.1 设备枚举与识别
`SetupDiGetClassDevs(GUID_DEVINTERFACE_DISK)` → `CreateFile` → `IOCTL_STORAGE_GET_DEVICE_NUMBER`
映射 `PhysicalDriveN` → `IOCTL_STORAGE_QUERY_PROPERTY(StorageDeviceProperty)` 取 Vendor/Product/Revision/Serial/BusType
→ `StorageAdapterProperty` 取总线与适配器 → `IOCTL_DISK_GET_DRIVE_GEOMETRY_EX` 取容量与扇区
→ `IOCTL_DISK_GET_DRIVE_LAYOUT_EX` + `IOCTL_VOLUME_GET_VOLUME_DISK_EXTENTS` 取分区与盘符。

**USB 硬盘盒识别**：`CM_Get_Parent` 上溯至 USB 枚举器 → `CM_Get_DevNode_PropertyW(DEVPKEY_Device_BusReportedDeviceDesc)`
与 `SPDRP_HARDWAREID` / `SPDRP_FRIENDLYNAME` 取 VID/PID 与桥接自报串（如 `RTL9210B-CG` / `ASM2362` / `JMicron`）
→ 叠加桥接特征库 → 得到 `UsbBridgeKind` 与建议协议梯。
热插拔：`CM_Register_Notification`（不轮询）。

### 4.2 层 1 · 原生引擎
1. `IOCTL_ATA_PASS_THROUGH_DIRECT`：SMART READ DATA `Features=0xD0, SectorCount=1, LbaLow=0x4F, LbaMid=0xC2, Command=0xB0`；
   THRESHOLD `0xD1`；RETURN STATUS `0xDA`；READ LOG `0xD5, LbaLow=日志地址`（0x01/0x06）；
   EXECUTE OFF-LINE IMMEDIATE `0xD4, LbaLow=子命令`（0x01 短 / 0x02 扩展 / 0x7F 中止）；
   IDENTIFY DEVICE `0xEC`（转速 w217、TRIM w169bit0、ZAC/ZBC w69、SATA 速率 w76-77、扇区 w106）。
   **缓冲区必须非分页且对齐**（`VirtualAlloc` / `AllocHGlobal`，不要托管 `byte[]`）。
2. `IOCTL_SCSI_PASS_THROUGH_DIRECT` + ATA PASS-THROUGH(16)（CDB `0x85`），USB-SATA 盒与 RAID 接管后的主路径：
   `[1]=protocol<<1`（3 非数据 / 4 PIO Data-In）、`[2]=t_length|t_dir|ck_cond`、`[3..4]=Features`、`[5..6]=SectorCount`、
   `[7..8]=LbaLow`、`[9..10]=LbaMid`、`[11..12]=LbaHigh`、`[13]=Device`、`[14]=Command`。
3. ATA PASS-THROUGH(12)（`0xA1`）+ LBA 字段字节序变体 —— 老桥接。
4. NVMe：`IOCTL_STORAGE_PROTOCOL_COMMAND` + `STORAGE_PROTOCOL_SPECIFIC_DATA` ——
   `NVMeDataTypeIdentify(0x01)`（CNS 1/2）、`NVMeDataTypeLogPage(0x02)` + `ProtocolDataRequestValue=0x02`（Health Log 512 B）、
   Log 0x01/0x05/0x06、`NVMeDataTypeDeviceCapabilities`（PCIe 链路）；`Command[0]=0x02`（Get Log Page）。

### 4.3 层 2 · smartctl 引擎
命令行 `smartctl -x -j [-d <mode>] <device>`；自检 `-t short|long`；中止 `-X`。
`-d` 表扩到 smartctl 全量：`sat / ata / scsi / nvme / usbjmicron / usbprolific / usbsunplus / usbasmedia /
sntjmicron / sntrealtek / jmb39x,N / jms56x,N / megaraid,N / aacraid,H,L,ID / 3ware,N / areca,N / hpt,N`。
**编排**：Native 先跑（20–80 ms，常驻轮询不卡）→ 失败转 smartctl → 两者都成功时**逐字段交叉校验**，不一致的字段在 UI 打标并记日志。

### 4.4 quirk 矩阵
| 桥接族 | 识别串 | 层 1 | 层 2 |
|---|---|---|---|
| 标准 SAT / UASP | 任意 | ATA PT-16 | `-d sat` |
| JMicron JMS578/579 | JMicron | PT-16 → PT-12 变体 | `-d usbjmicron` |
| JMicron JMB39x（多盘位） | JMB39x | PT-16 + LUN 选口 | `-d jmb39x,N` |
| JMicron JMS583/586 | JMS58x | 隧道族 A | `-d sntjmicron` |
| ASMedia ASM1153E/1351 | ASMedia | ATA PT-16 | `-d usbasmedia` |
| ASMedia ASM2362/2364 | ASM236x | 隧道族 B | `-d sntasmedia` |
| ASMedia ASM1352R（双盘位） | — | PT-16 + LUN | `-d usbasmedia,N` |
| Realtek RTL9210/9211/9212 | RTL92 | 隧道族 C | `-d sntrealtek` |
| Realtek RTL9220DP | RTL9220 | 隧道族 C2 | `-d sntrealtek` |
| Sunplus / Prolific / Cypress / IODATA / Logitec | 各自 VID | 老 CDB 变体 | `-d usbsunplus / usbprolific` |
| RAID 卡后的盘 | — | — | `-d megaraid,N / aacraid / 3ware` |
| 完全不透传 | 任意 | 全失败 | 输出结论 + 换 UASP 盒 / 直连建议 |

SMART 命令超时 3–5 s（SCSI 默认 10 s 会卡 UI）；全部后台线程 + CancellationToken；单盘失败不影响其它盘。

### 4.5 属性解码
`data/smart-attributes.json`：由 CDI 语言包脚本转换，含通用表 + NVMe 表 + 43 个厂商节；
每条 `id / nameCn / nameEn / unit / rawDecode / severity / category`，
`rawDecode ∈ lba48_to_bytes | nvme_data_unit | hours | minutes | temp_c | bitfield | plain`。
`data/drivedb-index.json`：从 drivedb.h 离线提取 型号 → 属性命名 / "(SMR)" / 控制器 / 转速。
**通电时间单位歧义**：部分盘属性 09 为分钟 → 首读按"数值差 ÷ 实测间隔秒数 × 3600"判定并缓存到 DiskKey 配置，UI 标注"已自动校正"。未知属性显示 `厂商定义 (0xNN)`，不隐藏不打分。

### 4.6 状态判定（原健康评分，已废弃）
基线公式（与参照一致，便于对照）：
`100 - (未通过自检 ? 40) - min(35, 15 + 重分配×3) - min(45, 20 + 待映射×5) - min(40, 20 + 离线不可校正×4)
 - (CRC>10 ? 5) - (氦气<100 ? Δ×1.5) - (温度>55 ? Δ×1.5)`，分级 ≥90 优秀 / ≥75 良好 / ≥50 注意 / <50 危险。
设计原则：**任何结论都必须能指回一个真实存在的 SMART 字段**。输出结构 = 四档状态 + 判定依据（来源属性/原始值/判读/建议）+ 已核对项清单（正常项也列出，让人看见核对了什么）。
纯函数化放 `Health/StatusVerdict.cs`，输入 SMART 数据模型输出判定，可单测、不依赖设备。

### 4.7 介质判定
SSD：NVMe 协议 / 存在 F1-F2 且有 AD 擦除计数 / 转速字段为固态（w217 = 0x0001 或 0）。
SMR：a) drivedb 官方 `(SMR)` 标注 → 100%；b) ATA ZAC/ZBC（w69）→ 100%；c) 型号正则库 → 99%；d) TRIM 旁证仅提置信度。
CMR：命中 CMR 型号库或既非 SMR 也非 Zoned。未知则明确显示"未收录，无法判定"，并给"实测法"入口（全盘曲线看掉速阶梯）。

### 4.8 基准测速
`DirectIoFile`：`CreateFileW` + `FILE_FLAG_NO_BUFFERING | FILE_FLAG_OVERLAPPED | FILE_FLAG_WRITE_THROUGH`，
`OVERLAPPED.hEvent` 提交 QD 个并发，缓冲区 4 KiB 对齐，偏移/长度按物理扇区对齐，结束 `FlushFileBuffers` + 删文件。
四组默认：SEQ1M Q8T1 / SEQ1M Q1T1 / RND4K Q32T16 / RND4K Q1T1。
可调：测试数据（0x00 / 随机 / 0xFF）、规模 16M–64G（默认 1 GiB）、次数 1–9、间隔 0/1/5/10 s、单位 MB/s|IOPS、显示状态 默认/峰值/演示、混合比 R70W30。
ATTO 阶梯 13 档 4K→16M。全盘顺序读曲线（1 MiB 块，只读）。随机访问 512B/4K/8K/16K/32K/64K/1M，跨 8/32 GB。
安全：写测试默认仅非系统盘；裸设备默认只读；测试文件前缀 `Gu-disk_bench_<guid>.tmp`，启动时清理残留。

### 4.9 表面扫描
卷内扫描（默认，安全）与裸盘只读全盘扫描（管理员）。错误码 `ERROR_CRC(23) / ERROR_SECTOR_NOT_FOUND(27) / ERROR_IO_DEVICE(1117)` 与超时都记为坏块。
输出：坏块表（LBA/大小/错误码/中文解释）+ LBA 热图（1 MiB 分桶）+ 实时速度与剩余时间 + 暂停/继续/停止 + CSV 导出。
长任务统一 `SetThreadExecutionState(ES_CONTINUOUS|ES_SYSTEM_REQUIRED)` 防休眠。

### 4.10 自检 / 日志 / AAM-APM
ATA `SMART EXECUTE OFF-LINE IMMEDIATE`（短/扩展，中止 0x7F）；NVMe Device Self-test（code 1/2，中止 0xF）。
日志：ATA SMART READ LOG 0x06（自检）/ 0x01（错误）；NVMe Log 0x06（20 条）/ 0x01（63 条）。
AAM/APM 滑块 + 推荐值 + 恢复默认，标注"不是所有盘支持"。自检期间 5 s 轮询且仅在该页激活时。

### 4.11 历史与报告
采样间隔 1/3/5/10/30/60 min；数值突变（温度 ±2 ℃、计数类任意变化）立即补点。
落盘 `%ROOT%/history/<DiskKey>/<Metric>.csv`（`timestamp,value`，与 CDI 同形）+ `meta.json` + `attributes.csv`；每指标保留 1 年，超出按每天 1 点 + 每周 1 点降采样。
支持导入 CDI 的 `Smart/<型号><序列号>/*.csv` 与 `Smart.ini`。
报告模板复用参照 `report_exporter.js`（改品牌），输出 HTML / TXT / JSON。

## 6. 权限与安全

必须管理员：SMART 透传、裸盘扫描、写基准。非管理员时枚举/识别/卷内只读基准可用，其余禁用并提供"以管理员重启"。
**绝不**：安装驱动、修改分区表、对系统盘做写测试、后台联网、上传数据。
危险操作二次确认：裸盘写测试、全盘扫描、自检。

## 9. 坑位清单

1. RAID/VMD（Intel RST、AMD RAID）接管盘 → ATA 直通失败；自动退回 SCSI SAT，再不行走 smartctl 适配器模式，并提示"盘被 RAID 驱动接管"。
2. `IOCTL_ATA_PASS_THROUGH_DIRECT` 缓冲区必须非分页对齐；用托管 `byte[]` 会随机失败。
3. 设备号漂移 → 持久化只用 DiskKey。
4. ATA 字符串是"以字为单位字节交换"，必须对调并裁空白。
5. 通电时间单位歧义（见 4.5）。
6. 多盘位盒每盘位是独立 LUN → 按 `PathId/TargetId/Lun` 定位。
7. SCSI 超时默认 10 s 会让 UI 假死 → 统一 3–5 s 并全部异步。
8. NVMe 多路温度传感器（0x12–0x19）→ 展示综合温度 + 各传感器，缺项 N/A 而非 0。
9. NO_BUFFERING 写测试真落盘 → 默认 128 MiB、系统盘默认禁止、明确提示。
10. smartctl 子进程冷启动 200–400 ms/盘 → 常驻轮询走 Native。
11. 沙箱内 `dotnet` 首跑会尝试建 `%USERPROFILE%/.dotnet` 被拒 → 构建脚本把 `DOTNET_CLI_HOME` / `NUGET_PACKAGES` 指到工作区；自包含发布需联网。
12. 参照素材：原件留工作区根的 `参考软件/`，提取物落 `reference/extracted/`；发布包只带 `data/` 与 `tools/smartctl/`。
