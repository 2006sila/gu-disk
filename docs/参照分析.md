# 参照软件解包分析

工作区根的 `参考软件/` 下 5 套参照，全部实际解包 / 读结构（非推测）。原件只读保留，可复用件由
`node tools/extract-reference.mjs` 提取到 `reference/extracted/`。

## 1. CrystalDiskInfo 9.6.0

形态：原生 PE32+/x64、2.77 MB、无壳、无 .NET。

读到的内容：

- `DiskInfo.ini` —— 全部开关。其中 `[USB]` 段就是它的 USB 桥接 quirk 全清单：
  `SAT / IODATA / Sunplus / Logitec / Prolific / JMicron / Cypress / ASM1352R / RTL9220DP / UsbMemory /
  NVMeJMicron / NVMeASMedia / NVMeRealtek`；
  `[Setting]` 段有 `AMD_RC2 / MegaRAID / IntelVROC / StartupWaitTime / Temperature / ResidentMinimize /
  SortDriveLetter / DriveMenu`。
- `CdiResource/dll/` —— 7 个桥接专用 DLL：`JMB39x64 / JMS56x64 / JMS586x64 / JMS586_40x64 / AMD_RC2t7x64`（各带 x86 版）。
  **我们不引用这些 DLL**，只用公开 IOCTL 实现等价隧道。
- `CdiResource/language/Simplified Chinese.lang` —— **61 个分节**，是本次最有价值的素材：
  `[Smart]` 通用属性表 + `[SmartNVMe]`（0x00–0x1D 对应 NVMe Health Log 字段）+ **43 个厂商节**
  （Kioxia / Ymtc / Maxiotek / Wdc / Samsung / Intel / Micron / SandForce / Phison / SiliconMotion /
  Marvell / Seagate / SanDisk / Realtek / SKhynix / Toshiba / Kingston / JMicron / Ssstc / Apacer / Scy / Recadata …），
  另有 `[Dialog]` / `[DiskStatus]` / `[Message]` / `[Alarm]` / `[Graph]` / `[HealthStatus]` 等文案节。
- `Smart/<型号><序列号>/*.csv` —— **用户 3 块盘的真实历史**，格式 `yyyy/MM/dd HH:mm:ss,值`；
  另有 `Smart.ini` 的 `[<key>FIRST]` / `[<key>]` / `[<key>THRESHOLD]` 三段。
- 关键换算：NVMe `1 data unit = 1000 × 512 B = 512 000 B`。
- 已知取舍：属性 09「通电时间」单位可能是小时也可能是分钟，CDI 有"检测单位（约 130 秒）"机制。

**取用**：属性名库、quirk 清单、历史 CSV 格式（我们格式兼容并可导入）、NVMe 字段映射。

## 2. CrystalDiskMark 8.0.1

形态：原生 x64、0.80 MB；带 `CdmResource/DiskSpd/DiskSpd64.exe`。

- `[Setting]` 语义：`TestData（0 随机 / 全 0）`、`Profile（0 默认 / 1 峰值 / 4 演示…）`、
  `Benchmark`、`TestUnit（MB/s | IOPS）`、`TestCount`、`TestSize`、`TestMix`（混合比）。
- `Themes/Shizuku/Demo-*.png` 是**真实界面截图**（6 档 DPI），可直接作结果布局参照。
- `theme.ini` 的配色令牌（LabelText / MeterText / ComboBk / Frame / Glass / Alpha…）。

**取用**：CDM 四组默认档的语义（SEQ1M Q8T1 / SEQ1M Q1T1 / RND4K Q32T16 / RND4K Q1T1）、
Profile 三态显示（默认/峰值/演示）、结果导出（文本 + 图片）。**它同时是 M3 的对标标尺。**

## 3. HD Tune Pro 6.0.0.5

原生 PE、1.22 MB、加壳无源码。功能面对照：基准（读写曲线）、文件基准、**随机访问（访问时间）**、
额外测试（传输速率 / 擦除）、**错误扫描（全盘坏块）**、健康（SMART）、AAM。

**取用**：功能定义 —— 全盘顺序曲线、随机访问测时、错误扫描三件套进我们 M3 / M4。

## 4. DiskGenius Pro 6.0.1

32 位、**UPX 加壳**、内含 7z 自解压、28.9 MB，是安装器。属分区与数据恢复域。

**取用**：仅作范围边界（我们明确不做分区编辑 / 文件恢复 / 克隆），不拆。

## 5. SMART Doctor 1.0.0 —— 本次信息量最大

形态：neutralinojs + WebView2 147，带 `tools/smartctl/smartctl.exe`（1.1 MB）+ `drivedb.h`（297 KB）。

**内嵌前端资源可直接从 exe 读出**（资源包 base 偏移 2 493 756，目录表内联），已切成 14 个文件：

| 文件 | 字节 | 用途 |
|---|---|---|
| `index.html` | 44 251 | 完整 UI 布局树（顶栏 / 侧栏 / 6 个 tab / 2 个模态） |
| `styles.css` | 45 416 | 全部 CSS 令牌与组件样式 |
| `js/disk_parser.js` | 61 741 | `SMART_ATTRIBUTES_DB`、`NVME_SMART_ATTRIBUTES_SPEC`、SMR/CMR 型号库、健康扣分式、单位换算 |
| `js/main.js` | 65 444 | 页面编排、状态机、渲染 |
| `js/report_exporter.js` | 33 473 | HTML / TXT 报告模板（含内嵌样式） |
| `js/system.js` | 21 667 | 管理员判定、设备枚举、USB 详情、提权流程 |
| `js/benchmark.js` | 11 194 | 13 档 ATTO 阶梯与柱状图数据模型 |
| `js/smart_runner.js` | 6 685 | 协议回退梯与 smartctl 调用行 |
| `js/mock_data.js` | 10 648 | 内置演示样本 |
| `js/neutralino.js` | 17 597 | 框架胶水 |
| `index.html 附带图标` | 3 个 | appIcon / logo.gif / trayIcon |

关键结论：

- 协议回退梯原文：`auto → sat → nvme → sntjmicron → usbjmicron → usbasmedia → sntrealtek`；
  命令行 `smartctl -x -j [-d <mode>] <device>`，自检 `-t short|long`，中止 `-X`。
- 健康扣分式原文：`100 - (未通过自检 40) - min(35,15+重分配×3) - min(45,20+待映射×5) - min(40,20+离线不可校正×4)
  - (CRC>10 ? 5) - (氦气<100 ? Δ×1.5) - (温度>55 ? Δ×1.5)`，分级 ≥90 / ≥75 / ≥50 / 其余。
- **它的"Direct I/O"是假的**：`benchmark_worker.ps1` 只用了 `FileOptions::WriteThrough`，
  **没有 FILE_FLAG_NO_BUFFERING**，结果受系统缓存影响。→ 这是我们的技术差异点。
- 界面语言：左侧 300px 文字菜单 + 顶部工具栏 + 圆角卡片 + 全 emoji 图标。**v2 外观已明确避开这套结构。**

**取用**：属性库与 SMR/CMR 型号库（逐函数翻译成 C#）、健康基线公式、报告模板（改品牌）、
benchmark 阶梯、`-d` 参数表、smartctl 引擎本身。**外观不取**（见 `docs/外观规范.md` 第 8 节差异表）。
